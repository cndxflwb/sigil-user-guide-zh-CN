自动化列表

— 单击一次执行一系列常规任务 —

许多 EPUB 开发者每次开始制作新 EPUB，或是清理从各种来源导入的 HTML，又或是为提交给出版商而保存 EPUB 做准备时，都会发现自己反复执行同一组任务。这些任务通常涉及按某种组合运行 Sigil 的内部命令/工具（例如修复并美化 HTML、更新 Manifest 属性等）和外部插件（例如 EPUBCheck、FolderIn、ePub3-itizer、Access-Aide 等）。

从 Sigil 1.8.0 开始，一项名为“自动化列表”的新功能使你可以创建一个常规任务列表，将其分配给三个运行自动化列表工具栏按钮之一，然后只需单击一次该按钮，即可按顺序运行整个任务列表。

创建与编辑自动化列表

要创建和编辑自动化列表，请按住三个自动化列表工具栏按钮之一，从下拉菜单中选择 编辑自动化列表。这将打开自动化列表编辑器。

要将 Sigil 工具添加到自动化列表，请单击添加工具按钮。这将打开一个可供选择的 Sigil 工具菜单。选择某个工具即可查看其功能说明。单击确定将其添加到自动化列表中。（由于许多 Sigil 工具需要用户交互才能发挥作用，目前并非所有 Sigil 工具都受支持。）

要运行带有“全部替换”的已保存搜索模板，你必须在 参数 列中输入该搜索模板的名称。你也可以运行已保存的搜索模板组，方法是输入组的名称并在其后加一个“/”。例如，假设你有一个名为“Automate Test”的搜索组，组内有两个名为 test1 和 test2 的搜索模板。如果你输入“Automate Test/”，该组中的所有搜索模板都会按顺序运行。如果你输入“Automate Test/test2”，则只有 test2 会运行。

要将插件添加到自动化列表，请单击添加插件按钮。这将打开一个菜单，列出你已安装的所有插件。（关于安装插件的更多信息，请参阅插件管理。）选择某个插件即可查看其功能说明。单击确定将其添加到自动化列表中。

创建自动化列表后，你可以选择某个命令并单击上移或下移按钮来更改任务的顺序。要移除某个命令，请选择它并单击移除。

由于随时可能发生意外的错误，建议以 RepoCommit 命令作为自动化列表的开头，为现有的 EPUB 创建一个完整的检查点。这样，如果自动化列表运行失败，你可以使用 Sigil 的检查点恢复功能轻松恢复整个 EPUB。（关于使用检查点的更多信息，请参阅使用检查点快速保存/恢复 EPUB 状态。）

自动化列表是简单的文本文件

自动化列表就是位于 Sigil 首选项文件夹根目录下的简单文本文件。它们的名称为：automate01.txt、automate02.txt 和 automate03.txt。因此，如果你愿意，可以使用任何文本编辑器来编辑它们。要直接跳转到 Sigil 首选项文件夹，请转到 编辑=>首选项（在 Mac 上：Sigil=>首选项），并单击左下角的打开首选项文件夹按钮。

下面是一个自动化列表文本文件的示例，可以在发布 EPUB 之前作为最终的清理与验证检查来运行：

# start with Checkpoint save to prevent any data loss
RepoCommit

# run a basic well-formed test before running any advanced tools
WellFormedCheckEpub

# prettify any code and fix any remaining html errors
MendPrettifyHTML

# clean up
DeleteUnusedMedia
DeleteUnusedStyles

# make sure styles are valid
ValidateStylesheetsWithW3C

# make an epub3 that works with epub2-only readers
GenerateNCXGuideFromNav

# update manifest properties
UpdateManifestProperties

# validate epub and save
EpubCheck
Save

虽然自动化列表工具栏按钮只有三个，但你可以创建任意数量的列表并将其保存在首选项文件夹中。要运行某个列表，你需要将其重命名为 automate01.txt、automate02.txt 或 automate03.txt，从而将其分配给三个工具栏按钮之一。

运行自动化列表

要运行自动化列表，只需单击相应的自动化列表工具栏按钮即可。

如果任何命令处理失败，自动化列表会立即终止。在列表执行期间，请留意 Sigil 状态栏中的信息。列表完成后，会显示一个对话框，其中包含自动化列表输出的完整日志，这样你就可以看到哪些成功了、哪些失败了，以及最重要的——原因。
