使用检查点快速保存/恢复 EPUB 状态

Sigil 提供了许多强大的工具，可自动修复、拆分、合并、重命名和移动 xhtml、图片、样式表及其他资源。这些工具可能产生大量更改，简单的撤销/重做难以应对。为防止意外丢失数据，并为更大规模的更改提供“撤销”途径，Sigil 新增了检查点功能。

检查点是 EPUB 完整状态的快速快照，保存在专属 git 仓库中；该仓库位于 Sigil 首选项文件夹内的“repo”目录。创建检查点很简单：点击检查点图标或使用检查点菜单即可。每个 EPUB 的检查点按顺序命名/编号。

创建检查点后，即可放心地对副本做更大的改动，需要时可轻松恢复到上一个检查点。

还可为每个检查点编辑并附加简短描述：选择 检查点=>编辑检查点描述，便于记录检查点处于编辑流程的哪个阶段。

可以选择并查看仅存在于当前 EPUB 或仅存在于检查点中的文件。

对于已修改的文本文件，会以并排高亮视图展示发生更改的行，以及行内具体的更改区域。

EPUB 最终版本制作并保存后，可管理检查点仓库，将其移除以释放磁盘空间。

还可生成每个检查点的更改摘要：选择 检查点=>显示检查点日志，便于需要时选择要恢复的较早版本。

某些 Sigil 工具（如 修复 或 修复并美化）会大量更改空白符，可能掩盖之后更重要的更改。因此，使用这类工具前和使用后建议立即各建一个检查点，以便日后更轻松地区分更改。

EPUB 的文件名和书名很容易更改（尤其在编辑期间），因此不宜将文件名或书名作为多次更改中锚定的唯一标识。为唯一标识你的 EPUB，若 尚不存在相应标识符，检查点工具会为其添加采用 UUID 方案的 dc:identifier。该标识符构成仓库名称的基础，编辑期间应保持不变。此 UUID 标识符不必是图书的 unique-identifier（唯一标识符），只需在您使用检查点工具期间保持不变即可。
